# L1.5G-A Prototype Extraction Matrix

Source prototype:
`C:\Projects\4veco\4veco-platform\knowledge\grafiekmeester_representatie_arena.html`

Verdict: useful design reference, not a direct code source.

## Keep For MVP

| Prototype idea | Keep as | Reason |
| --- | --- | --- |
| `bron -> waarden -> berekening` learning rhythm | Core feedback model | This matches the desired graph-reading behavior: first inspect the source, then select values, then calculate. |
| Bar-chart value reading | MVP challenge type | Small, visual, directly useful for 1.1.2 and 1.1.3. |
| Line-chart value reading | MVP challenge type | Natural bridge from graph reading to percentage/index change. |
| Old/new value selection before calculation | MVP challenge type | Reinforces the same procedure discipline as the percentage/index paragraphs. |
| Step-by-step feedback | Required answer feedback | Students need to see which graph value was used and why. |
| Simple SVG chart rendering | Platform utility candidate | Reusable if separated from prototype state and challenge generation. |
| Keyboard-clickable answer choices | Accessibility requirement | Keep the interaction pattern, but rebuild under platform UI conventions. |

## Defer

| Prototype idea | Defer until | Reason |
| --- | --- | --- |
| XP, stars, level, streak | After MVP proves learning value | Motivational system adds state complexity before the core graph task is proven. |
| Campaign and free-training modes | Later game-product sprint | Too much navigation/state for the first platform engine. |
| Full skill tree | Later progression sprint | Broad skill universe is not paragraph-scoped and risks becoming a second curriculum map. |
| Badges | Later motivation sprint | Not needed to prove graphical learning. |
| Coach panel | Later feedback/coaching sprint | Could imply diagnostics or adaptive coaching too early. |
| Pie-chart share/percentage-point tasks | Later graphical expansion | Useful, but not needed for the first bar/line MVP. |
| Producer graphs and profit graphs | Later Book 1/Book 2 economics graph sprint | Too far beyond the first graph-reading proof. |
| Elasticity and market graph tasks | Later domain sprint | High semantic and PV-alignment risk. |
| Random challenge generators | After data-schema validator exists | First platform MVP should use explicit challenge records that can be validated. |
| localStorage progress state | After adaptive seam contract | L1.5G-B should define the safe storage contract first. |

## Reject For Direct Port

| Prototype element | Reject as | Reason |
| --- | --- | --- |
| Single-file HTML/CSS/JS architecture | Platform implementation pattern | Platform needs engine, UI, CSS, data, shell generator, tests, and lesson output separated. |
| Hard-coded broad skill universe | Student-facing semantic model | It duplicates curriculum/PV concepts without governance. |
| Prototype `STORE_KEY` progress model | Shared production storage | Needs a common adaptive seam and no behavior change with empty payload. |
| Implicit mastery percentages | Product claim | PV-G4 still blocks mastery routing and diagnostics. |
| Broad all-domain progression | First MVP scope | It would make the sprint impossible to review cleanly. |
| Direct PV projection | Governance violation | PV-G4 allows alignment/validation only, not student-facing projection. |

## First MVP Cut

MVP name working label: `grafieken-spel` or `grafieklezer`.

Recommended first challenge records:

1. Read a value from a bar chart.
2. Read a value from a line chart.
3. Select old and new values from a bar or line chart, then calculate
   percentage change.

Recommended first pilot:

- technical pilot: bounded sandbox or `1.1.2 Percentages en indexcijfers`;
- production regression: L1.6, preferably `1.1.3 Grafieken en tabellen`.

## PV Boundary

The MVP may include internal fields that allow later validation against PV
visual-state or procedure records. It may not show PV IDs to students and may
not claim that PV records are student-facing.
