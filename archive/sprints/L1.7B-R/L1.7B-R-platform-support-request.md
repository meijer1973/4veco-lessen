## Product Requirements

The checkpoint MVP should:

- include 3 to 5 short tasks;
- cover paragraph target skills only;
- use the shared `SkillMapEngine` `exit-ticket` request in compact checkpoint
  mode;
- show student-facing skill labels only;
- use local practice-progress language;
- give immediate neutral feedback;
- offer retry/self-check guidance;
- optionally suggest which existing practice route to use next, using
  non-diagnostic wording such as "Oefen dit nog met Redeneren".

The checkpoint MVP must not:

- use mastery/pass/fail/score/grade/evidence language;
- present percentage scores or pass thresholds;
- describe itself as a diagnostic, test, exam, summative assessment, or
  personal learning path;
- read adaptive payloads to change task order, focus, difficulty, visibility, or
  route;
- store machine evidence for teacher/product decisions;
- expose internal IDs such as `A61`;
- authorize adaptive diagnostics, mastery, sequencing, student-facing AI,
  summative use, PV projection, or PV machine promotion.

## Required Platform Tests

Minimum tests should prove:

- the engine validates data shape for 3 to 5 checkpoint tasks;
- task checking returns neutral feedback without scores/pass/fail/mastery;
- retry/self-check state is local practice state only;
- the exit ticket requests `SkillMapEngine.createRequest("exit-ticket", ...)`
  in compact mode;
- no internal MTU IDs are visible in rendered route text;
- blocked terms do not appear in student-visible strings:
  `mastery`, `pass`, `fail`, `score`, `grade`, `summative`, `diagnose`,
  `adaptive`, `evidence`;
- shell generator loads `skill-map-engine.js`, `skill-map-route-ui.js`,
  `exit-ticket-engine.js`, `exit-ticket-ui.js`, and `exit-ticket.css`;
- deploy includes exit-ticket engine files and shell generation;
- landing-page `Check` appears only when a generated exit-ticket page exists.
