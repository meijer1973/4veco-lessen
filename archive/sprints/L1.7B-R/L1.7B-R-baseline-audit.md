# L1.7B-R Baseline Audit

Date: 2026-05-25
Status: COMPLETE FOR PLATFORM-HANDOFF DECISION

## Audit Question

Can L1.7B-R safely implement the exit-ticket MVP now, or must it first hand off
to platform `GAME-UX-2`?

## Findings

### 1. L1.7B-C stopped for valid reasons

The prior L1.7B-C records show that the local prototype is design evidence
only. It is not source-controlled product code and it used unsafe product
language and behavior:

- mastery / pass / score / evidence semantics;
- adaptive-focus payloads;
- machine-check claims;
- target-exercise mastery framing;
- pass thresholds and phase-pass logic.

Those semantics conflict with the non-summative checkpoint contract.

### 2. GAME-UX-1 removed one blocker

Platform `GAME-UX-1` added the shared skill-map engine with:

- compact, route, and restricted full modes;
- aspect filters;
- local-practice-only progress;
- request support for future `exit-ticket` consumers;
- forced-false product boundary flags.

This means compact checkpoint mode now exists. It does not by itself provide an
exit-ticket engine or generated output.

### 3. Landing-page integration is ready to consume generated output

The current platform landing generator has a scoped `Check` hook:

- `scanFiles()` detects an `exit-ticket.html` or equivalent generated page;
- `sectionAvailability()` adds `Check` only when that generated page exists;
- `renderParagraafPage()` shows a `Check` section only when
  `files.check.exitTicket` is present.

This is the right generator-owned pattern. No hand-patched landing link is
needed.

### 4. Platform support lane is not active yet

The platform reference roadmap has a future row:

`GAME-UX-2 | Exit Ticket Checkpoint Engine MVP`

That row explicitly describes the needed platform support for lesson L1.7B-R.
It also says this lane is future/not active before:

- a lesson L1.7B-R platform-support request; and
- upstream platform gate status being resolved or explicitly waived.

Therefore the lesson sprint should not bypass `GAME-UX-2` by editing platform
runtime code ad hoc from the lesson side.

### 5. No generated lesson output should be changed in this pass

Because the platform engine/wrapper is not yet approved for implementation, no
exit-ticket lesson HTML, shared data, landing-page `Check` activation, or
screenshot QA output is generated in this pass.

## Decision

Implementation is paused. L1.7B-R should issue a precise platform support
request to `GAME-UX-2` and record a stop decision.

## Required Next State Before Resuming

Resume only after platform confirms one of these:

- `GAME-UX-2` is active and may implement the source-controlled checkpoint
  engine/wrapper; or
- a human decision explicitly waives the `GAME-UX-2` timing prerequisite while
  preserving all product-use boundaries.
