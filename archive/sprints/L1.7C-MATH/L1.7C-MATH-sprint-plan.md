platform workflow and should refresh at minimum:

- L1.7C-MATH technical QA and human-review packet records.

No generated lesson output may be hand-patched.

## Operational Procedure

1. Confirm the old math skill-tree surfaces still exist and identify which
   paragraphs have both `wiskundevaardigheden.html` and `stappenplan.html`.
2. Audit the four-part architecture against current runtime behavior:
   - math skill-tree game;
   - reasoning game;
   - graph game;
   - shared skill-map display layer.
3. Update the platform landing generator so the primary `Rekenen` route points
   to `wiskundevaardigheden.html` when it exists.
4. Keep `stappenplan.html` visible as support, step/procedure practice, or
   `Extra steun`; do not hide it.
5. Review whether the old math skill-tree page starts in a safe scoped
   calculation-practice view or an overloaded full catalog. If the full catalog
   remains the default, record and fix or explicitly carry that as a scale
   blocker.
6. Ensure the shared skill-map route/display layer still gives consistent
   language across math, reasoning, graph, exit-ticket, and landing contexts.
7. Regenerate through platform scripts only.
8. Run focused landing/game-row tests and current student-web validators for
   the affected paragraphs.
9. Record screenshot or browser evidence for the restored math primary route,
   the retained `stappenplan` support route, and the three-game row.
10. Prepare student-experience, teacher-learning-quality, and lead-review
    packets before closure.

## Acceptance Criteria

- The primary `Rekenen` landing route links to the old skill-tree math game
  when `wiskundevaardigheden.html` exists.
- `Stappenplan` remains visible and usable as support or extra step practice.
- The landing page does not present `stappenplan` as the replacement for the
  math practice game.
- The math, reasoning, and graph games use coherent shared skill-map language.
- The full skill-map display is not an accidental default full catalog unless
  human review explicitly accepts that for controlled pilot use.
- Technical validation and human review decide whether the restored math route
  can be used before Scale Gate 1.

## Stop Conditions

- Stop if restoration requires hand-editing generated lesson output.
- Stop if the old math skill-tree game still uses mastery, diagnostic,
  sequencing, grading, summative, AI, PV, or automatic progression language in
  visible copy.
- Stop if the platform generator cannot represent both a primary math game and
  a support `stappenplan` route without a platform refactor.
- Stop if restoring the math route would hide the procedure/stappenplan support
  surface.
- Stop if the four-part architecture cannot be verified from current platform
  source and generated output.
