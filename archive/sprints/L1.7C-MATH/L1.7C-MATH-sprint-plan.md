# L1.7C-MATH Sprint Plan

Date: 2026-05-26
Status: PLANNED; HARD BLOCKER BEFORE SCALE GATE 1; NOT STARTED

## Sprint Name

Restore Skill-Tree Math Game + Four-Game Architecture Integrity

## Original Specification

The game row must contain three aspect-specific practice engines plus one
shared route/skill-map layer:

- `Redeneren`
- `Rekenen` / old skill-tree math practice
- `Grafieken`
- shared skill-map / route-display layer

`Stappenplan` is procedure support. It is not the replacement for the math
skill-tree game.

## Purpose

Restore the old `wiskundevaardigheden` skill-tree math game as the primary
`Rekenen` practice route while keeping the `stappenplan` game as support. This
is a restoration/integrity sprint, not cosmetic cleanup: the current primary
math route no longer matches the original game-row specification.

## Operational Procedure

1. Confirm which paragraphs have:
   - `wiskundevaardigheden.html`;
   - `stappenplan.html`;
   - `redeneer-spel.html`;
   - `grafiekenspel.html`.
2. Audit the four-part architecture against current runtime behavior:
   - math skill-tree game;
   - reasoning game;
   - graph game;
   - shared skill-map display layer.
3. Update the platform landing generator so the primary `Rekenen` route points
   to `wiskundevaardigheden.html` when it exists.
4. Keep `stappenplan.html` visible as `Rekenstappen`, `Stappenplan`, procedure
   support, or `Extra steun`; do not hide it.
5. Review whether the old math skill-tree page starts in a safe scoped
   calculation-practice view or an overloaded full catalog.
6. For each game type, prove:
   - it requests the correct aspect scope;
   - it does not default to the full catalog;
   - it can show the skill tree or route for that skill type;
   - it uses student-facing labels, not internal IDs;
   - it avoids diagnostics, mastery, sequencing, grades, summative use, AI, and
     PV claims.
7. Add tests:
   - landing route points to `wiskundevaardigheden.html` when present;
   - `stappenplan.html` remains visible as support;
   - each game can access the shared skill-map route layer;
   - no full catalog is the default student view;
   - internal IDs are not visible.
8. Regenerate through platform scripts only.
9. Record screenshot or browser evidence:
   - `1.1.2` landing with primary `Rekenen` restored;
   - `1.1.2` math skill-tree page after JS loads;
   - `1.1.3` graph route;
   - reasoning route;
   - desktop/mobile/light/dark where relevant.
10. Prepare student-experience, teacher-learning-quality, and lead-review
    records before closure.

## Acceptance Criteria

- The primary `Rekenen` landing route links to the old skill-tree math game
  when `wiskundevaardigheden.html` exists.
- `Stappenplan` remains visible and usable as support or extra step practice.
- The landing page does not present `stappenplan` as the replacement for the
  math practice game.
- Redeneren, Rekenen, and Grafieken all consume or expose the shared skill-map
  route language in the correct aspect scope.
- The skill tree shown to a student is scoped to the relevant skill type by
  default.
- The full skill-map display is not an accidental default full catalog.
- Technical validation and human review decide whether the restored math route
  can be used before Scale Gate 1.
- PASS WITH FLAGS is allowed only for issues outside the core game-row
  architecture. Failure to restore the primary math route is REVISE/PAUSE, not
  a carry flag.

## Stop Conditions

- Stop if restoration requires hand-editing generated lesson output.
- Stop if the old math skill-tree game still uses mastery, diagnostic,
  sequencing, grading, summative, AI, PV, or automatic progression language in
  visible copy.
- Stop if the platform generator cannot represent both a primary math game and
  a support `stappenplan` route without a platform refactor.
- Stop if restoring the math route would hide the procedure/stappenplan support
  surface.
- Stop if the four-part architecture cannot be verified from current platform
  source and generated output.
