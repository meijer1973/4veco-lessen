# L1.7C-MATH History Audit

Date: 2026-05-26
Status: BASELINE AUDIT; RESTORATION NOT STARTED

## Question

What happened to the old `wiskundevaardigheden` skill-tree math game, and how
does that affect the intended four-part game architecture?

## Short Finding

The old skill-tree math game was not deleted. It still exists as
`wiskundevaardigheden.html` and still uses the `skilltree-*` runtime. The
problem is that L1.7D made `stappenplan.html` the primary `Rekenen` landing
route whenever a `stappenplan` file exists, and moved the old math skill-tree
surface into `Verdiep` as `Volledige vaardigheidskaart`.

That is a core game-row specification regression. `Stappenplan` is useful
support, but it is not the original math game and should not silently replace
the primary math practice route. This should have been treated as REVISE/PAUSE,
not as an ordinary carry flag.

## Evidence

### Old math game still exists

Current lesson output still contains:

- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree-engine.js`
- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree-ui.js`
- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree.css`
- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree/1.1.1.js`
- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree/1.1.2.js`
- `Boek 1 - Grondslagen, vraag en aanbod/shared/skilltree/1.1.3.js`
- paragraph `wiskundevaardigheden.html` pages.

For example, `1.1.2 Percentages en indexcijfers - wiskundevaardigheden.html`
loads `skilltree/base-elements.js`, paragraph skill-tree data,
`adaptive-seam.js`, `skill-map-engine.js`, `skilltree-engine.js`, and
`skilltree-ui.js`.

### L1.7C-0 intended four pieces

L1.7C-0 defined:

- three practice engines:
  - `Redeneren`
  - `Rekenen`
  - `Grafieken`
- one shared skill-map / skill-tree display and route layer.

The contract said the shared skill-map engine is not the fourth game. It is the
common progression, filtering, recommendation, and route-display layer.

### GAME-UX-1 implemented platform support, not lesson routing

Platform GAME-UX-1 added:

- `skill-map-engine.js`
- aspect-filtered route views
- compact/route/full modes
- hooks for reasoning, calculation/procedure, graphical, exit-ticket, and
  landing-preview consumers
- local practice-progress language changes.

GAME-UX-1 did not generate lesson output and did not remove the old skill-tree
math game.

### L1.7C reviewed `Stappenplan/Rekenen`

L1.7C regenerated Book 1 game-row surfaces and reviewed:

- `Redeneren`
- `Stappenplan/Rekenen`
- `Grafieken`

The sprint carried a flag that `Rekenen` was still a procedure/stappenplan
practice engine, not a full numeric calculation engine. It did not close the
question of whether the old skill-tree math game should remain the primary
math practice game.

### L1.7D displaced the old math game on the landing page

L1.7D landing IA changed the generator so the visible `Rekenen` route uses:

```js
const calculationRoute = files.oefenen.stappenplan || files.oefenen.wiskundevaardigheden;
```

When both surfaces exist:

- `Rekenen / stappenplan` links to `stappenplan.html`;
- `wiskundevaardigheden.html` appears under `Verdiep` as
  `Volledige vaardigheidskaart`.

This is the visible displacement the user noticed.

## Current Architectural Problem

The visible product no longer reflects the intended four-part model:

1. math skill-tree practice game;
2. reasoning practice game;
3. graph practice game;
4. shared skill-map / route-display layer.

Instead, the primary game row currently behaves like:

1. reasoning game;
2. procedure/stappenplan support game;
3. graph game;
4. full skill-tree page hidden as advanced/deepen material.

That is not the intended architecture.

## Required Correction

L1.7C-MATH must:

- restore `wiskundevaardigheden.html` / the old skill-tree math game as the
  primary `Rekenen` practice route;
- keep `stappenplan.html` visible as support, step/procedure practice, or
  `Extra steun`;
- audit whether the old skill-tree math game now consumes the shared
  skill-map language safely;
- ensure the math game does not expose a full unfiltered catalog by default if
  that would overload students;
- re-check the alignment among the math skill-tree game, reasoning game, graph
  game, and shared skill-map display layer before Scale Gate 1.
- classify any remaining issue against the REV-STD-1 levels. Failure to
  restore the primary skill-tree math route is a `core_spec_failure`, not a
  `minor_carry_flag`.

## Boundary

This audit does not authorize generated-output hand patches, diagnostics,
mastery decisions, automatic sequencing, grading, summative use,
student-facing AI, PV projection, PV machine promotion, broad companion
scaling, CP-6 closure, or Year-1 closure.
