## Operational Procedure

1. Trace the current checkpoint metadata route from platform source data to
   generated lesson output.
2. Compare `targetSkillIds` and `skillScopeIds` with paragraph-plan skills,
   MTU ids, and target-exercise references.
3. Decide the authoritative exit-ticket metadata route:
   paragraph-plan skills, MTU ids, target-exercise skills, or a reviewed
   mapping layer.
4. If platform support is required, write a precise platform handoff before
   changing generated lesson output.
5. Regenerate only through platform workflow if source changes are made.
6. Add validation/tests proving the mapping cannot silently drift.
7. Write a technical QA report and human-review packet before closure.

## Acceptance Criteria

- `A43`/`A04` versus `B01`/`B02` is either fixed or represented by a reviewed
  mapping layer.
- The accepted metadata route is documented.
- Student-facing text still contains no internal IDs.
- Tests or validators cover the accepted route.
- Human review decides whether exit-ticket metadata may be used for later
  target-readiness or scale evidence.

## Stop Conditions

- Stop if the work requires hand-patching generated lesson output.
- Stop if the mapping would authorize diagnostics, mastery, sequencing,
  summative use, PV projection, PV machine promotion, target-exercise
  promotion, CP-6 closure, Year-1 closure, or broad scaling.
- Stop if platform support is needed but not explicitly scoped.
