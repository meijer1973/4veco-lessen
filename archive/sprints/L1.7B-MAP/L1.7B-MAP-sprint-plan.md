## Sprint Name

Exit Ticket Skill-Metadata Alignment

## Original Specification

The exit ticket must cover the paragraph's target skills and support a
student-facing self-check. Its metadata must be trustworthy before the output
can be used as target-exercise-readiness evidence, scale evidence, or any
source-of-truth skill claim.

## Purpose

Resolve or map the `A43`/`A04` versus `B01`/`B02` mismatch in the current
`1.1.1` exit-ticket checkpoint. This mismatch was accepted as a carried flag
for the first checkpoint, but it may not be carried into target-exercise
readiness, broad scaling, diagnostic evidence, mastery evidence, sequencing
evidence, PV evidence, target-exercise promotion, or CP-6/Year-1 evidence.

## Required Decision

Decide and implement one authoritative metadata route:

- paragraph-plan skill IDs;
- MTU IDs;
- target-exercise skill IDs;
- reviewed mapping layer between namespaces.

The preferred route is a reviewed mapping layer if the platform currently has
multiple valid skill namespaces.

## Operational Procedure

1. Trace current metadata through:
   - platform source data;
   - generated lesson output;
   - paragraph plan;
   - target-exercise registry;
   - MTU/procedure registry.
2. Define a metadata contract:
   - visible task label;
   - paragraph skill;
   - MTU/procedure unit where available;
   - target-exercise operation;
   - practice-route suggestion.
3. Decide the authoritative exit-ticket metadata route.
4. If platform support is required, write a precise platform handoff before
   changing generated lesson output.
5. Add validation that no checkpoint can claim target-exercise readiness if
   metadata is unmapped.
6. Add validation that no checkpoint can activate `Check` if target/scope
   metadata is invalid for the intended product role.
7. Preserve the rule that no internal IDs appear in student-facing copy.
8. Regenerate only through platform workflow if source changes are made.
9. Write a technical QA report and human-review packet before closure.

## Acceptance Criteria

- `A43`/`A04` versus `B01`/`B02` is either fixed or represented by a reviewed
  mapping layer.
- The accepted metadata route can support paragraph-plan skills and
  target-exercise-readiness evidence.
- The accepted mapping is documented.
- Tests or validators prevent silent metadata drift.
- Student-facing text still contains no internal IDs.
- Human review explicitly states whether exit-ticket metadata may be used for
  later target-readiness evidence.

## Stop Conditions

- Stop if the work requires hand-patching generated lesson output.
- Stop if the mapping would authorize diagnostics, mastery, sequencing,
  summative use, PV projection, PV machine promotion, target-exercise
  promotion, CP-6 closure, Year-1 closure, or broad scaling.
- Stop if the team cannot identify a stable source of truth.
- Stop if platform support is needed but not explicitly scoped.
