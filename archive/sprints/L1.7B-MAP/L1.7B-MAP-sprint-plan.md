# L1.7B-MAP Sprint Plan

Date: 2026-05-26
Status: READY FOR HUMAN REVIEW; NOT CLOSED

## Sprint Name

Exit Ticket Skill-Metadata Alignment

## Original Specification

The exit ticket must cover the paragraph's target skills and support a
student-facing self-check. Its metadata must be trustworthy before the output
can be used as target-exercise-readiness evidence, scale evidence, or any
source-of-truth skill claim.

This sprint is not allowed to make the existing `1.1.1` checkpoint look like a
target-exercise-readiness product unless the data actually covers the target
exercise operation chain. If the checkpoint remains a paragraph-skill check,
its metadata must say so.

## Purpose

Resolve or map the `A43`/`A04` versus `B01`/`B02` mismatch in the current
`1.1.1` exit-ticket checkpoint. This mismatch was accepted as a carried flag
for the first checkpoint, but it may not be carried into target-exercise
readiness, broad scaling, diagnostic evidence, mastery evidence, sequencing
evidence, PV evidence, target-exercise promotion, or CP-6/Year-1 evidence.

## Required Decision

Decide and implement one authoritative metadata route:

- checkpoint-assessed paragraph skills;
- target-exercise required skills;
- skill-map display/request skills;
- any reviewed mapping layer between namespaces.

The preferred route is a reviewed mapping layer if the platform currently has
multiple valid skill namespaces.

Current baseline facts to verify:

- `1.1.1` paragraph plan identifies `B01` and `B02` as the paragraph skills.
- `course-target-exercises.json` identifies `A43`, `B01`, and `B02` as target
  exercise skills for `1.1.1`.
- existing checkpoint source data declares `A43` and `A04` as
  `targetSkillIds`/`skillScopeIds`.
- `A04` is substitution and is not part of the `1.1.1` target exercise record.
- the current checkpoint task content visibly checks scarcity/opportunity-cost
  concepts, not the full `A43` mixed-allocation calculation chain.

## Operational Procedure

1. Trace current metadata through:
   - platform source data;
   - generated lesson output;
   - paragraph plan;
   - target-exercise registry;
   - MTU/procedure registry.
2. Record the trace in `L1.7B-MAP-baseline-audit.md`.
3. Define a metadata contract:
   - visible task label;
   - checkpoint-assessed paragraph skill;
   - target-exercise required skill;
   - skill-map display/request scope;
   - practice-route suggestion.
4. Decide the authoritative exit-ticket metadata route.
5. If platform support is required, write a precise platform handoff before
   changing generated lesson output.
6. Add validation that no checkpoint can claim target-exercise readiness if
   metadata is unmapped.
7. Add validation that no checkpoint can activate `Check` if target/scope
   metadata is invalid for the intended product role.
8. Preserve the rule that no internal IDs appear in student-facing copy.
9. Regenerate only through platform workflow if source changes are made.
10. Write validation, technical QA, and human-review packet records before
    asking for closure.

## Required Technical Checks

Run the narrowest useful checks first, then broader checks if generated output
changes:

- focused Jest for exit-ticket metadata/engine behavior;
- platform deploy/generation;
- `validate-paragraph` for `1.1.1` in complete mode;
- Book 1 health check;
- any focused student-web or link/data check needed to prove the generated
  checkpoint still loads and `Check` remains scoped.

If a full platform Jest run is skipped, record why. If deploy changes lesson
output, inspect the generated diff before committing.

## Acceptance Criteria

- `A43`/`A04` versus `B01`/`B02` is either fixed or represented by a documented
  metadata contract.
- The accepted metadata route can support paragraph-plan skills and
  target-exercise-readiness evidence.
- The current `1.1.1` checkpoint does not claim target-exercise readiness unless
  it covers the `A43`/`B01`/`B02` target-exercise operation chain.
- The accepted mapping is documented.
- Tests or validators prevent silent metadata drift.
- Student-facing text still contains no internal IDs.
- Human review explicitly states whether exit-ticket metadata may be used for
  later target-readiness evidence.

## Stop Conditions

- Stop if the work requires hand-patching generated lesson output.
- Stop if the mapping would authorize diagnostics, mastery, sequencing,
  summative use, PV projection, PV machine promotion, target-exercise
  promotion, CP-6 closure, Year-1 closure, or broad scaling.
- Stop if the team cannot identify a stable source of truth.
- Stop if platform support is needed but not explicitly scoped.
