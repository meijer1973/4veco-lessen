## Source-Of-Truth Findings

`references/SOURCE_OF_TRUTH.md` says:

- `references/machine/` is canonical for platform IDs, unit relationships,
  terms, and machine-readable metadata.
- `references/owned/` and authored target-exercise records define course
  intent and target-exercise alignment, but owned prose alone may not mint or
  mutate machine units.
- sprint metadata records process state; it does not make a pedagogical claim
  true.

Therefore the sprint may not solve the mismatch by inventing new local IDs or
by treating the old carried flag as evidence. It must align to existing
machine-unit IDs and explicitly document what the checkpoint does and does not
prove.

## Current Mismatch Before Fix

Before L1.7B-MAP implementation, the generated lesson checkpoint and platform
source both declared:

```text
targetSkillIds: A43, A04
skillScopeIds: A43, A04
```

This was wrong for two reasons:

- `A04` is `Substitueren`; it is not part of the `1.1.1` paragraph plan or
  the `1.1.1` target-exercise registry record.
- the visible checkpoint tasks check scarcity and opportunity-cost concepts,
  not substitution.

## Paragraph Plan Alignment

The `1.1.1` paragraph plan identifies these paragraph skills:

- `B01` — `Schaarste als kerneconomisch probleem`
- `B02` — `Alternatieve kosten in een keuze-situatie`

The four visible checkpoint tasks align with these concepts:

- recognizing scarcity;
- identifying scarce means;
- selecting opportunity costs;
- explaining why free can still involve scarcity.

## Target-Exercise Alignment

The active target-exercise registry records `1.1.1` required skills as:

```text
A43, B01, B02
```

`A43` is `Totale winst uit gemengde allocatie berekenen`. It requires applying
opportunity-cost reasoning to a mixed allocation/profit context.

The current checkpoint does not yet cover the full `A43` operation chain. It is
therefore not target-exercise-readiness evidence.

## Skill-Map Runtime Finding

`skilltree/base-elements.js` currently exposes the interactive A-domain slice
to the shared skill-map runtime. `B01` and `B02` exist in the canonical MTU
registry, but they are not currently represented as interactive skill-tree
nodes.

That means L1.7B-MAP should not hide the mismatch by retaining `A43/A04` as the
checkpoint scope. The correct fix is to make checkpoint metadata honest:

- assessed paragraph skills: `B01/B02`;
- target-exercise required skills: `A43/B01/B02`;
- target-readiness evidence: `false` until a later Q2 checkpoint covers the
  complete operation chain.

## Decision

Proceed with a platform source-data and engine validation update:

- replace `A43/A04` checkpoint target/scope metadata with `B01/B02`;
- add a `metadataAlignment` object;
- mark `targetReadinessEvidence: false`;
- add tests that reject target-readiness claims when target-exercise skills are
  not covered;
- regenerate lesson output through platform deploy only.

No generated lesson output may be hand-patched.
