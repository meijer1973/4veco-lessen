# L1.7B-MAP Metadata Contract

Date: 2026-05-26
Status: IMPLEMENTED FOR `1.1.1`; HUMAN REVIEW REQUIRED BEFORE CLOSURE

## Product Rule

Exit-ticket metadata must say what the checkpoint actually checks. It may not
borrow target-exercise, skill-map, or MTU IDs to make a partial checkpoint look
like target-exercise-readiness evidence.

## Fields

### `targetSkillIds`

The checkpoint-assessed skill IDs: the paragraph skills the visible tasks
actually check.

For `1.1.1` after L1.7B-MAP:

```json
["B01", "B02"]
```

### `skillScopeIds`

The checkpoint's local scope for the compact skill-map request. For this sprint
it must match the assessed paragraph skills.

For `1.1.1` after L1.7B-MAP:

```json
["B01", "B02"]
```

### `metadataAlignment.paragraphSkillIds`

The paragraph-plan skills. For `1.1.1`:

```json
["B01", "B02"]
```

### `metadataAlignment.targetExerciseSkillIds`

The required skills from the active target-exercise registry. For `1.1.1`:

```json
["A43", "B01", "B02"]
```

### `metadataAlignment.targetReadinessEvidence`

Boolean claim flag.

- `false`: the checkpoint is a paragraph-skill checkpoint, not readiness
  evidence for the paragraph target exercise.
- `true`: allowed only when the checkpoint covers the complete reviewed
  target-exercise operation chain.

For `1.1.1` after L1.7B-MAP:

```json
false
```

### `metadataAlignment.status`

Allowed current status for `1.1.1`:

```text
paragraph_skill_aligned_not_target_readiness
```

A future readiness checkpoint may use:

```text
target_exercise_readiness_aligned
```

only if `targetReadinessEvidence` is `true` and the checkpoint covers all
target-exercise skill/operation requirements.

## Validation Rules

The platform exit-ticket engine now validates:

- `targetSkillIds` and `skillScopeIds` are non-empty string arrays;
- `metadataAlignment` exists;
- `paragraphSkillIds` and `targetExerciseSkillIds` are non-empty string arrays;
- `targetReadinessEvidence` is a boolean;
- `targetSkillIds` include all `paragraphSkillIds`;
- `skillScopeIds` include all `paragraphSkillIds`;
- target-readiness status cannot be claimed unless
  `targetReadinessEvidence: true`;
- target-readiness evidence cannot be claimed unless all
  `targetExerciseSkillIds` are covered by `targetSkillIds`.

The focused metadata test also verifies that `1.1.1`:

- uses `B01/B02` for checkpoint target/scope;
- does not use `A04`;
- records `A43/B01/B02` as the target-exercise skill set;
- keeps `targetReadinessEvidence: false`.

## Boundaries

This contract does not authorize:

- diagnostics;
- mastery decisions;
- automatic sequencing;
- grading or summative use;
- student-facing AI;
- PV projection;
- PV machine promotion;
- target-exercise promotion;
- CP-6 or Year-1 closure;
- Scale Gate 1;
- broad companion scaling.

## Follow-Up

`L1.7B-Q2` must still produce a genuine target-exercise-readiness checkpoint
before stronger readiness copy is allowed. For `1.1.1`, that would require
covering the `A43` mixed-allocation calculation/choice chain as well as
`B01/B02`.
