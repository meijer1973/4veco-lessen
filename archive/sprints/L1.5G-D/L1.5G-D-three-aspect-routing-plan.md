# L1.5G-D Three-Aspect Game Routing Plan

Date: 2026-05-17
Owner: Codex main agent
Status: closed PASS

## Purpose

Make the paragraph landing page show the game layer as three clear learning
routes instead of a flat pile of game tiles:

- Redeneren
- Rekenen
- Grafieken

This sprint does not add new game behavior. It makes the existing routes
student-facing and concept-facing so a student can choose the right kind of
practice and a teacher can explain why each route exists.

## Work

1. Define a small platform-owned game aspect taxonomy inside the landing-page
   generator:
   - reasoning: `Redeneren`
   - calculation: `Rekenen`
   - graphical: `Grafieken`
2. Attach aspect metadata to the generated game cards:
   - student label
   - student-facing route description
   - stable `data-learning-aspect` attribute for future generator/report use
   - domain token class for light/dark styling
3. Render the Oefenen section as:
   - an aspect route grid when two or more aspect routes exist;
   - a separate guided-practice subroute for `Begeleide inoefening` when present.
4. Keep the copy student-facing:
   - no internal unit codes;
   - no PV/projection wording;
   - no adaptive, diagnostic, mastery, sequencing, AI, or summative claims.
5. Update tests so the generated landing page must contain the aspect labels
   and must not regress to user-facing `HTML`/Word labels.

## Explicit Non-Goals

- no new graphical-game challenge types;
- no game engine refactor;
- no adaptive behavior;
- no advisor or recommendation system;
- no student-facing diagnostics;
- no mastery, sequencing, AI, or summative use;
- no PV machine promotion;
- no student-facing PV projection;
- no teacher/student review gate; L1.5G-E owns that formal gate.

- requires editing generated lesson HTML by hand;
- turns the aspect layer into an advisor or recommendation engine;
- makes adaptive or diagnostic claims visible to students;
- exposes internal unit or PV codes;
