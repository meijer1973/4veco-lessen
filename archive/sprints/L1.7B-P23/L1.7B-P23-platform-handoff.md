# L1.7B-P23 Platform Handoff

Date: 2026-05-26
Status: REQUIRED BEFORE GENERATED `1.1.2` / `1.1.3` EXIT-TICKET OUTPUT

## Handoff Summary

The lesson team should not generate exit-ticket checkpoints for `1.1.2` or
`1.1.3` with the current exit-ticket engine. The current platform engine and UI
support only choice tasks, while the target exercises require calculation,
unit/notation, table/graph interaction, interpolation, graph construction, and
short explanation.

## Required Platform Capability

Add an exit-ticket task model that can support these task families:

| Task family | Needed for | Minimum behavior |
|---|---|---|
| `numeric_input` | percentage change, index number, graph reading | Accept numeric answer with tolerance, rounding policy, and expected unit/notation. |
| `calculation_work` | percentage/index operation chains | Capture selected old/new/base values, calculation expression or staged work, and final answer. |
| `unit_or_notation_input` | percent/index distinction | Require `%`, `index`, `indexpunten`, `ongeveer`, or no unit where appropriate. |
| `short_response` | index-point trap, graph-claim explanation | Capture a student explanation and compare with a reviewed local answer model without AI or summative scoring. |
| `table_value_select` | table reading and claim checking | Let students select labelled values from a table and carry them into a calculation. |
| `graph_read` | values and interpolation | Render a graph and accept a value read from the graph, including approximate answers. |
| `graph_construct_or_axis_check` | economic axis convention and graph drawing | At minimum check axis assignment and point placement; full graph drawing may be a later task family if reviewed. |

## Metadata Contract Requirements

Future generated checkpoint data must continue to distinguish:

- checkpoint-assessed paragraph skills;
- target-exercise required skills and operations;
- task-level operation coverage;
- skill-map display/request scope;
- `targetReadinessEvidence`.

`targetReadinessEvidence` may be true only when the checkpoint covers the
complete reviewed target-exercise operation chain, not merely all named skill
IDs.

## Validation Requirements

Platform validation should reject:

- target-readiness claims when required operation coverage is incomplete;
- generated checkpoints whose task types cannot check the declared operations;
- choice-only readiness checks for target exercises that require calculation,
  units, graph/table interaction, or constructed response;
- internal skill IDs in student-facing copy;
- diagnostics, mastery, sequencing, grading, summative, student-facing AI, PV,
  CP-6, Year-1, target-exercise promotion, or scale claims.

## UI/Accessibility Requirements

The UI must support:

- keyboard-only entry and selection;
- visible focus states;
- mobile and desktop layout without horizontal overflow;
- light/dark readability;
- graph/table labels that remain readable at small widths;
- neutral local feedback and practice links;
- no automatic route decisions.

## Paragraph-Specific Minimums

### `1.1.2`

Must check:

- old/new value selection;
- percentage-change calculation;
- index-number calculation;
- index-point versus percentage distinction;
- final answer with correct percentage/index notation;
- short explanation for the index-point trap.

### `1.1.3`

Must check:

- table heading, label, and unit reading;
- economic axis convention;
- graph drawing or reviewed axis/point-placement substitute;
- graph reading and interpolation;
- table/graph value percentage claim evaluation;
- short explanation.

## Product Boundaries

This handoff does not authorize target-exercise readiness, diagnostics,
mastery decisions, automatic sequencing, grading or summative use,
student-facing AI, PV projection, PV machine promotion, target-exercise
promotion, CP-6 or Year 1 closure, Scale Gate 1, or broad companion scaling.
