## Sprint Name

Exit Ticket Target-Skill Pilots For 1.1.2 And 1.1.3

## Original Specification

The exit ticket should cover the paragraph's target skills and help decide
whether the student is ready to try the paragraph target exercise. The first
`1.1.1` checkpoint only checks a conceptual subset; it does not prove that the
exit-ticket system can handle calculation/index or graph/table skills.

## Purpose

Create reviewed checkpoint pilots or precise stop/handoff decisions for:

- `1.1.2 Percentages en indexcijfers`
- `1.1.3 Grafieken en tabellen`

These paragraphs introduce important skill types not tested by the `1.1.1`
checkpoint. The sprint may not produce weak MC-only checks unless the paragraph
target exercise is itself MC-like.

## Operational Procedure

For each paragraph:

1. Extract the paragraph target exercise.
2. Decompose it into an operation chain.
3. Identify what the exit ticket must check.
4. Decide whether the current exit-ticket engine can support the required task
   types:
   - calculation field;
   - final answer field;
   - unit/percentage field;
   - graph/table interaction;
   - short constructed response.
5. If the engine cannot support the required type, stop and write a platform
   handoff. Do not force everything into multiple choice.
6. If generation proceeds, use platform source/generators only.
7. Keep `Check` hidden until each paragraph has reviewed generated checkpoint
   output.
8. Record technical QA, screenshot/interaction QA, student review, and
   teacher-learning-quality review.

## Required Coverage

For `1.1.2`, the checkpoint must cover:

- selecting old and new value;
- calculating percentage change;
- calculating an index number;
- distinguishing index points from percentage change;
- writing a final answer with percentage/index notation.

For `1.1.3`, the checkpoint must cover:

- reading table headings, row labels, column labels and units;
- applying the economic axis convention;
- reading a value from a graph;
- interpolating between graph points;
- judging a graph/percentage claim.

## Acceptance Criteria

The sprint can close with either:

- reviewed generated checkpoints for both `1.1.2` and `1.1.3`; or
- precise stop decisions and platform handoffs for unsupported task types.

It may not close with two MC-only checks that do not cover the target-exercise
operation chains.

## Stop Conditions

- Stop if the current UI cannot safely check calculation/index or graph/table
  skills.
- Stop if the math route remains unresolved by L1.7C-MATH.
- Stop if metadata remains unresolved by L1.7B-MAP.
- Stop if generated output would require hand patches.
- Stop if `Check` would activate before reviewed generated output exists.
