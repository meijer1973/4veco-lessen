## Sprint Name

Exit Ticket Pilot Coverage For 1.1.2 And 1.1.3

## Purpose

Create reviewed checkpoint pilots or operational stop/handoff decisions for
`1.1.2 Percentages en indexcijfers` and `1.1.3 Grafieken en tabellen`. These
paragraphs introduce calculation, index, graph, and table skills that the
`1.1.1` checkpoint does not test.

## Operational Procedure

1. Audit target exercises and answer models for `1.1.2` and `1.1.3`.
2. Define the minimum exit-ticket operation chain for each paragraph.
3. Identify UI needs before building:
   - calculation field;
   - answer field;
   - unit or percentage field;
   - graph/table reading interaction;
   - short constructed response where needed.
4. Decide whether current GAME-UX-2 runtime can support each pilot or whether
   platform support is required first.
5. If generation proceeds, use platform source/generators only.
6. Keep `Check` hidden until each paragraph has reviewed generated checkpoint
   output.
7. Record technical QA, screenshot/interaction QA, student review, and
   teacher-learning-quality review.

## Acceptance Criteria

- `1.1.2` and `1.1.3` each have either a reviewed generated checkpoint pilot or
  a precise stop decision with platform handoff.
- Calculation/index and graph/table requirements are explicit.
- UI changes needed for calculation and graph reading are recorded.
- No checkpoint claims mastery, sequencing, diagnostics, summative use, PV, or
  broad readiness.

## Stop Conditions

- Stop if the current UI cannot support required calculation or graph reading
  tasks safely.
- Stop if generated output would require hand patches.
- Stop if `Check` would be activated without reviewed generated checkpoint
  output.
