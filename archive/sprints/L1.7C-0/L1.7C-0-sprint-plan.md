## Work Procedure

1. Inspect the current skill-tree, landing, and game-row integration points.
2. Record a current-state audit with the exact gaps that matter for L1.7C.
3. Write the shared skill-map engine contract:
   - modes;
   - aspect filters;
   - state semantics;
   - recommended-next-skill behavior;
   - request/response API;
   - integration expectations for each practice engine;
   - exit-ticket compact checkpoint use;
   - landing-page route preview use;
   - accessibility and screenshot expectations;
   - product-use boundary language.
4. Update `lessen-team-roadmap.md` so L1.7C-0 is closed and L1.7C becomes the
   next active lesson sprint.
5. Update the platform reference roadmap so `GAME-UX-1` points at the finished
   L1.7C-0 contract rather than a pending lesson dependency.
6. Run roadmap/index validation and focused existing skill-tree/landing tests.
7. Commit and push both repositories so GitHub reviewers see the current state.

## Acceptance Criteria

- The contract defines one shared route/progression layer, not a fourth game.
- The contract defines `compact`, `route`, and `full` modes.
- The contract defines `reasoning`, `calculation`, `graphical`, and explicit
  `mixed` aspect filters.
- The contract specifies that full catalog views are not student defaults.
- The contract defines how `Redeneren`, `Rekenen`, and `Grafieken` request a
  scoped skill route.
- The contract defines how the exit ticket can use compact checkpoint mode.
- The contract defines how landing pages can show route previews without
  becoming a card dump or full catalog.
- State/progress language avoids mastery, grading, diagnostics, sequencing,
  student-facing AI, summative use, PV projection, and PV machine promotion.
- Mobile, dark-mode, and keyboard accessibility expectations are explicit.
- L1.7C has enough contract detail to start a game-row quality-upgrade sprint.

## Stop Conditions

- Stop if the work would hand-patch generated lesson output.
- Stop if the contract needs protected reference mutation or unit minting.
- Stop if the shared engine would make mastery, diagnostic, automatic
  sequencing, grading, or summative claims.
- Stop if the exit-ticket prototype would need to be imported or shipped before
  source-control and product-boundary issues are resolved.
- Stop if L1.7C cannot start without a platform implementation sprint first;
  record that dependency explicitly instead of pretending the game-row work is
  ready.
