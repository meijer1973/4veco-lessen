## Sprint Name

Exit Ticket Target-Equivalent Proof Implementation

## Original Specification

The exit ticket is the paragraph target-equivalent proof task. A short
non-summative advisory checkpoint is not the final product when the product
specification requires proof that the student can perform the same
target-exercise operation chain at the same level.

## Purpose

Upgrade one exit-ticket checkpoint into target-equivalent proof. The checkpoint
must test the same operation and answer-form chain as the paragraph target
exercise, not merely a short recall check. The output remains non-summative,
but it should answer: "Has this student locally demonstrated that they can
complete the paragraph target exercise?"

## Recommended Paragraph

Start with `1.1.2 Percentages en indexcijfers`.

Reason:

- it forces calculation input;
- it forces final-answer notation;
- it forces percentage/index distinctions, including D31 index points versus
  percent;
- it is technically easier than graph drawing but stronger than conceptual MC.

After `1.1.2`, repeat the pattern for `1.1.3`.

## Operational Procedure

1. Select one paragraph for the prototype.
2. Name the paragraph target exercise.
3. Write or cite the answer model.
4. Decompose the target exercise into operations.
5. Design checkpoint tasks that cover every operation.
6. Include the required answer forms:
   - calculation/work field;
   - final answer field;
   - percentage/index/unit field;
   - short explanation where needed.
7. Explicitly check D31: 108 to 112 is 4 index points, not 4 percent, and the
   correct percentage change is about 3.7 percent.
8. Align metadata with paragraph-plan skills and target-exercise skills.
9. Keep target-equivalent completion language blocked until `GATE-L1.7B-Q2`.
10. Generate output only through platform workflow.
11. Add tests for:
   - operation-chain coverage;
   - answer-model alignment;
   - unit/percentage validation;
   - D31 index-point versus percentage-change distinction;
   - no mastery/diagnostic/sequencing language;
   - no internal-ID leakage.
12. Validate with technical QA, screenshot/interaction QA,
    student-experience review, and teacher-learning-quality review.

## Acceptance Criteria

- The checkpoint covers the target-exercise operation and answer-form chain at
  the same cognitive level.
- A student who completes the checkpoint correctly has locally and
  non-summatively demonstrated the target-exercise chain, pending
  `GATE-L1.7B-Q2` approval of completion language.
- The checkpoint remains non-summative.
- It does not claim mastery.
- Metadata alignment is accepted.
- Answer-model alignment is documented.
- D31 is explicitly checked as student action, not only mentioned in feedback.
- Required input/UI types work for the selected paragraph.
- Teacher-learning-quality review accepts the operation-chain coverage.
- Student-experience review accepts clarity and feedback.
- PASS WITH FLAGS is allowed only for issues outside the target-equivalent
  specification. Missing operation-chain coverage is REVISE/PAUSE.

## Stop Conditions

- Stop if the platform cannot support calculation or answer fields.
- Stop if target-equivalent proof can only be checked through teacher grading.
- Stop if the checkpoint would need diagnostic/mastery/sequencing claims to
  work.
- Stop if generated output would require hand patches.
- Stop if D31 cannot be checked explicitly.
- Stop if completion language is requested before `GATE-L1.7B-Q2`.
