# L1.7B-Q2 Sprint Plan

Date: 2026-05-26
Status: PLANNED; NOT STARTED

## Sprint Name

Exit Ticket Target-Exercise Readiness Prototype

## Purpose

Upgrade one exit-ticket checkpoint from a non-summative practice check into a
target-exercise-readiness prototype. The goal is to test whether a student is
ready to try the paragraph target exercise, not merely whether the student can
answer a short recall check.

## Operational Procedure

1. Select one paragraph for the prototype.
2. Name the paragraph target exercise and answer model.
3. Decompose the target exercise into an operation chain.
4. Design checkpoint tasks that cover the operation chain.
5. Add required answer forms:
   - calculation input;
   - final answer input;
   - unit or percentage input;
   - graph/table interpretation;
   - reasoning or short constructed response.
6. Align metadata with paragraph-plan skills and target-exercise skills.
7. Generate output only through platform workflow.
8. Validate with technical QA, screenshot/interaction QA, answer-model
   alignment, student-experience review, and teacher-learning-quality review.

## Acceptance Criteria

- The checkpoint covers the target-exercise operation chain.
- Answer-model alignment is documented.
- Required input/UI types work for the selected paragraph.
- Metadata alignment is accepted.
- Feedback remains non-summative and practice-oriented.
- Review accepts the prototype as target-exercise-readiness evidence or records
  the remaining blockers.

## Stop Conditions

- Stop if the checkpoint needs mastery, grades, sequencing, diagnostics,
  summative claims, student-facing AI, or PV behavior to work.
- Stop if platform input/UI support is insufficient and no platform handoff is
  written.
- Stop if generated output would require hand patches.
- Stop if target-exercise readiness depends on the calculation route while
  L1.7C-MATH has not restored or explicitly resolved the primary math-game
  route.
