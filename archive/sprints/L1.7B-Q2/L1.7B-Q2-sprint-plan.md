## Sprint Name

Exit Ticket Target-Exercise Readiness Prototype

## Original Specification

The exit ticket should check whether the student has reached the paragraph
goals and is ready to attempt the paragraph target exercise. A short
non-summative checkpoint is not the final product when the original assignment
requires target-exercise readiness.

## Purpose

Upgrade one exit-ticket checkpoint into target-exercise-readiness evidence. The
checkpoint must test the operation chain needed for the paragraph target
exercise, not merely a short recall check. The output remains non-summative,
but it should answer: "Is this student ready to try the target exercise?"

## Recommended Paragraph

Start with `1.1.2 Percentages en indexcijfers`.

Reason:

- it forces calculation input;
- it forces final-answer notation;
- it forces percentage/index distinctions;
- it is technically easier than graph drawing but stronger than conceptual MC.

After `1.1.2`, repeat the pattern for `1.1.3`.

## Operational Procedure

1. Select one paragraph for the prototype.
2. Name the paragraph target exercise.
3. Write or cite the answer model.
4. Decompose the target exercise into operations.
5. Design checkpoint tasks that cover every operation.
6. Include the required answer forms:
   - calculation/work field;
   - final answer field;
   - percentage/index/unit field;
   - short explanation where needed.
7. Align metadata with paragraph-plan skills and target-exercise skills.
8. Generate output only through platform workflow.
9. Add tests for:
   - operation-chain coverage;
   - answer-model alignment;
   - unit/percentage validation;
   - no mastery/diagnostic/sequencing language;
   - no internal-ID leakage.
10. Validate with technical QA, screenshot/interaction QA,
    student-experience review, and teacher-learning-quality review.

## Feedback Boundaries

Allowed:

- `Bekijk deze stap nog eens.`
- `Je hebt deze check afgerond.`
- `Je bent klaar om de eindopgave te proberen.` only after Q2 proves
  target-exercise-readiness coverage.

Prohibited:

- `Je beheerst dit.`
- `Geslaagd.`
- `Niveau vastgesteld.`
- `Automatisch door naar...`
- grade, mastery, diagnostic, sequencing, summative, AI, PV, CP-6, Year-1, or
  promotion claims.

## Acceptance Criteria

- The checkpoint covers the target-exercise operation chain.
- A student who completes the checkpoint correctly has plausibly demonstrated
  readiness to try the target exercise.
- The checkpoint remains non-summative.
- It does not claim mastery.
- Metadata alignment is accepted.
- Answer-model alignment is documented.
- Required input/UI types work for the selected paragraph.
- Teacher-learning-quality review accepts the operation-chain coverage.
- Student-experience review accepts clarity and feedback.
- PASS WITH FLAGS is allowed only for issues outside the target-readiness
  specification. Missing operation-chain coverage is REVISE/PAUSE.

## Stop Conditions

- Stop if the platform cannot support calculation or answer fields.
- Stop if readiness can only be checked through teacher grading.
- Stop if the checkpoint would need diagnostic/mastery/sequencing claims to
  work.
- Stop if generated output would require hand patches.
- Stop if target-exercise readiness depends on the calculation route while
  L1.7C-MATH has not restored or explicitly resolved the primary math-game
  route.
