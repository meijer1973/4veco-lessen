# L1.5O Output Profile Simplification Plan

Date: 2026-05-12

## 1. Decision

Before building paragraph 1.1.2, split paragraph outputs into explicit profiles.

The default companion path is now **student web**:

- student-facing HTML pages;
- interactive HTML games;
- presentation HTML plus editable PPTX where the presentation itself is required;
- source markdown, paragraph plan, review records, quality-ref, game data, and assets.

Office documents are no longer default completion artifacts. They become an
explicit **office export** profile for teacher handout/editing needs.

The three textbook PDFs (`paragraaf.pdf`, `opgaven.pdf`, `antwoorden.pdf`) are
not normal companion output. They belong to a careful **publisher print**
pipeline and should be generated/reviewed there instead of inside the fast
student-web build.

## 2. Scope

Platform changes:

- update `validate-paragraph.js` so `--profile student-web` is the default;
- keep `--profile legacy-full` for the old 27-file companion contract;
- add `--profile publisher-print` for the print/PDF gate;
- allow `--profile office` when Office exports are deliberately required;
- update validator tests for the new profiles;
- update `BUILD-PARAGRAPH.md` and `build-scripts/README.md`.

Lesson-repo changes:

- update `lessen-team-roadmap.md`;
- keep the sprint plan/log in this file.

Out of scope:

- deleting existing 1.1.1 Word/PDF files;
- rebuilding 1.1.2 content;
- redesigning the publisher print pipeline;
- converting old DOCX-first builders to web-native authoring in this sprint.

## 3. Output Policy

### student-web

Required Part A:

- markdown source files;
- generated web pages for the same surfaces;
- `build_pdf.py` may exist but PDFs are not required;
- assets and quality records remain required.

Required Part B:

- HTML companions and games;
- `presentatie.pptx` remains required while the presentation is an editable
  teacher deliverable;
- `index.html`;
- shared game data;
- `_paragraph-plan.md`;
- companion review.

Not required:

- `.docx` files;
- differentiated static DOCX handouts;
- static helper DOCX;
- textbook PDFs.

### legacy-full

Requires the previous 27 Part B files, including all DOCX files, for regression
or old-workflow checks.

### office

Requires the student-web profile plus Office exports. This is opt-in and should
be used only when a teacher-facing editable/exportable document package is the
requested product.

### publisher-print

Requires the textbook PDF set and print-related checks. This profile is meant
for the separate publisher pipeline, not for routine paragraph companion work.

## 4. Procedure

1. Add profile parsing to the paragraph validator.
2. Refactor required-file lists into profile-aware manifests.
3. Update tests to prove student-web passes without DOCX/PDF files.
4. Keep legacy-full passing on the old 27-file fixture.
5. Update docs so paragraph 1.1.2 starts from the lighter default.
6. Run targeted tests and `validate-paragraph` against 1.1.1 in the relevant
   profiles.
7. Update the roadmap with the new gate before L1.4.

## 5. Acceptance Tests

- `node node_modules/jest/bin/jest.js scripts/tests/validate-paragraph.test.js scripts/tests/validate-paragraph-modes.test.js`
- `node scripts/validate-paragraph.js --mode complete --profile student-web "<1.1.1 paragraph>"`
- `node scripts/validate-paragraph.js --mode complete --profile legacy-full "<1.1.1 paragraph>"`
- `node scripts/validate-paragraph.js --mode part-a --profile publisher-print "<1.1.1 paragraph>"`

## 6. Stop Conditions

Stop before L1.4 if:

- student-web validation still requires Word documents;
- publisher PDFs are still implicitly required in the normal complete profile;
- legacy-full compatibility is broken without an explicit decision;
- roadmap/docs still describe the old 27-file contract as the default.
