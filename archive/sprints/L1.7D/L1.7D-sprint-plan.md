# L1.7D Sprint Plan - Paragraph Landing Page Information Architecture Cleanup

Date: 2026-05-24
Status: CLOSED PASS WITH FLAGS

## Purpose

L1.7D prevents companion product sprawl before broad scaling. Paragraph landing
pages must become a controlled learning route rather than a file/card dump.

The route should guide students through:

1. `Start`
2. `Leer`
3. `Oefen`
4. `Check` when a reviewed exit-ticket surface exists
5. `Verdiep` / sources / downloads

The landing page must consume the L1.7C-0/L1.7C shared skill-map/game
architecture. The second-row practice routes should appear as a scoped game row
(`Redeneren`, `Rekenen/Stappenplan`, `Grafieken`) rather than as three unrelated
skill-tree cards or a full unfiltered catalog.

## Operational Procedure

1. Record this plan and a baseline audit before implementation.
2. Define a landing-page IA contract that classifies surfaces as primary,
   secondary/collapsed, advanced, teacher/download-only, or not yet available.
3. Implement only through the platform landing-page generator. Do not hand-patch
   generated lesson `index.html` files.
4. Regenerate Book 1 through `scripts/deploy.js`.
5. Update focused tests for landing hierarchy, no hidden Word-download leakage,
   route availability, and no blocked product-use language.
6. Run validation:
   - focused landing-page Jest;
   - deploy link/data checks;
   - complete student-web validation for `1.1.1`, `1.1.2`, and `1.1.3`;
   - Book 1 health;
   - v5 target-exercise count validation;
   - screenshot/browser QA for representative landing pages in desktop/mobile
     and light/dark modes.
7. Record technical QA, validation log, and a human-review packet. Do not close
   the sprint without student-experience, teacher-learning-quality, and lead
   review records.

## Acceptance Criteria

- Default visible paragraph route is `Start`, `Leer`, `Oefen`, optional `Check`,
  and `Verdiep`.
- `Check` is not shown as a real route unless a reviewed exit-ticket surface
  exists.
- `Oefen` presents scoped practice routes, not an unfiltered skill catalog.
- `Rekenen` routes to the procedure/stappenplan practice surface when it exists;
  the full `wiskundevaardigheden` skill map is secondary/advanced.
- Secondary/context surfaces are collapsed or demoted:
  `samenvatting`, `nieuws met visual`, `nieuws-detective`, `YouTube`,
  `presentatie`, textbook material, PDFs, and teacher/download surfaces.
- `1.1.1` does not promise a graph route when no graph route exists.
- All generated landing links remain reachable.
- No adaptive diagnostics, mastery, sequencing, grading/summative, AI, PV
  projection, or PV machine-promotion language is introduced.
- Desktop/mobile and light/dark screenshot evidence exists for representative
  landing pages.

## Stop Conditions

- Stop if the fix would require hand-patching generated landing pages.
- Stop if a visible `Check`/exit-ticket route would need to imply a finished
  checkpoint that does not exist yet.
- Stop if landing copy introduces adaptive, diagnostic, mastery, sequencing,
  grading/summative, student-facing AI, PV projection, or PV machine-promotion
  claims.
- Stop if deploy regenerates unrelated rich companion documents or Part A
  textbook files.
- Stop if validators pass technically but the route hierarchy remains a peer
  file/card dump.
