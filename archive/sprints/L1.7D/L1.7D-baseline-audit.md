## Baseline Strengths

- Paragraph, chapter, and book landing pages are generator-owned.
- The game row already carries `data-learning-aspect` for reasoning,
  calculation, and graphical routes.
- L1.7C fixed the previous internal-ID leak in route panels.
- `1.1.1` landing copy no longer promises graph practice when no graph route
  exists.
- Legacy Word exercise rows are hidden from the default student landing page.

## Baseline Problems For L1.7D

| Problem | Evidence | Risk |
| --- | --- | --- |
| Route labels are old workflow labels, not the intended scalable route. | Student sees `Voorbereiden`, `Oefenen`, `Leren`, `Lesboek`, not `Start`, `Leer`, `Oefen`, `Check`, `Verdiep`. | Students must infer the learning order. |
| `Oefenen` appears before `Leren`. | Generated section order places practice before explanation. | Weaker students may jump into practice without seeing the main skill explanation. |
| Many secondary surfaces are peer cards. | Presentation, YouTube, news, summary, textbook, and downloads all appear as cards. | Scaling will repeat clutter across paragraphs. |
| `Rekenen` points at `wiskundevaardigheden`. | The calculation route card uses `wiskundevaardigheden.html`; L1.7C accepted the current calculation role as `Stappenplan/Rekenen`. | The default route can still feel like a full skill-tree/catalog entry instead of focused practice. |
| No `Check` support state is defined. | Exit ticket is not implemented after L1.7B contract-and-stop. | The generator must not imply a finished checkpoint surface. |

## Baseline Decision

Proceed with a platform-generator change only. The landing page should:

- show direct cards only for the primary route;
- place secondary/context/source/download surfaces behind collapsed details;
- use `Stappenplan/Rekenen` as the calculation practice route when available;
- keep `wiskundevaardigheden` as secondary/advanced full skill-map access;
- hide `Check` until an exit-ticket file exists and has a reviewed workflow.
