# L1.7B Stop Decision

Date: 2026-05-23
Status: IMPLEMENTATION PAUSED

## Decision

Do not build or import the exit-ticket MVP in L1.7B.

Record the companion-completion contract and move the next active dependency
to L1.7C-0, the shared skill-map engine contract.

## Why

The inspected prototype is useful, but not safe as a direct implementation.

Blockers:

1. The prototype exists only as an untracked platform zip, so GitHub reviewers
   cannot inspect it as repo state.
2. The prototype uses mastery/score/pass/evidence language, including
   `Mastery-eis`, pass thresholds, score percentages, and copied machine
   evidence.
3. The prototype reads adaptive-focus payload keys and highlights tasks from
   that payload.
4. L1.7B requires a compact checkpoint-mode skill-map relationship, but the
   shared skill-map contract does not exist yet.
5. Importing the prototype now would risk creating a fourth isolated game UI
   before the shared route/progression architecture exists.

## What Is Accepted From L1.7B

Accepted outputs:

- prototype inventory;
- complete companion-set contract;
- future MVP scope;
- explicit stop decision.

The exit ticket remains a required pre-scale surface, but it is not yet a
student-facing generated artifact.

## Next Sprint

Proceed to:

```text
L1.7C-0 — Shared Skill-Map Engine Contract
```

That sprint should define the compact checkpoint mode that the future exit
ticket must consume.

## Future Resume Conditions

Resume exit-ticket implementation only when:

- L1.7C-0 defines compact checkpoint mode and scoped skill routes;
- platform `GAME-UX-1` has an implementation path or accepted architecture;
- the exit-ticket source is imported or rewritten as source-controlled platform
  code;
- all mastery, grading, diagnostic, adaptive, sequencing, summative, PV, and
  AI language is removed or blocked by tests;
- the MVP plan includes human-review and screenshot/interaction QA.

## Not Authorized

This stop decision does not authorize:

- generated lesson-output mutation;
- exit-ticket landing-page publication;
- target-exercise final review;
- protected reference mutation;
- diagnostics;
- adaptive routing;
- mastery or sequencing;
- student-facing AI;
- summative use;
- PV projection;
- PV machine promotion.
