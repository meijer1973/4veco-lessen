# L1.7B Companion Completion Contract

Date: 2026-05-23
Status: CONTRACT DRAFT; IMPLEMENTATION BLOCKED UNTIL L1.7C-0/GAME-UX-1

## Purpose

Define the complete paragraph companion set before more surfaces are scaled.
The contract prevents product sprawl by giving every surface a role in the
student route.

## Student Route

The scalable route should be:

```text
Start -> Leer -> Oefen -> Check -> Verdiep / Docent / Downloads
```

## Surface Contract

| Route Layer | Student Role | Default Visibility | Surfaces |
| --- | --- | --- | --- |
| Start | Activate prior knowledge and orient the paragraph | primary | `uitleg voorkennis`, paragraph overview |
| Leer | Teach the core procedure/concept with dual coding | primary | `uitleg vaardigheden`, presentation when used in class |
| Oefen | Practise with support and with aspect-specific games | primary group, not file dump | `begeleide inoefening`, `Redeneren`, `Rekenen`, `Grafieken` |
| Check | Short non-summative checkpoint after practice | primary after MVP review | exit ticket |
| Verdiep | Reinforce and contextualize | secondary/collapsed | `samenvatting`, `nieuws met visual`, optional video/context |
| Lesboek | Textbook source and printable material | secondary | paragraaf/opgaven/antwoorden, PDFs where relevant |
| Docent/downloads | Teacher or downloadable assets | collapsed/teacher-facing | PPTX, PDFs, source/download surfaces |

## Exit Ticket Role

The exit ticket is a checkpoint, not an assessment engine.

It should:

- contain 3-5 short tasks;
- cover the paragraph's target skills;
- give immediate feedback and self-check guidance;
- suggest a next practice route when helpful;
- use the shared skill-map engine in compact checkpoint mode after L1.7C-0;
- preserve all product-use boundaries.

It must not:

- grade students;
- claim mastery or final competence;
- make diagnostic claims;
- route adaptively;
- sequence learning automatically;
- use student-facing AI;
- claim summative validity;
- project PV records to students;
- promote any PV machine state.

## Skill-Map Dependency

The exit ticket should not invent its own skill route UI.

After L1.7C-0, it should consume the shared skill-map engine in compact
checkpoint mode:

```text
mode: compact
scope: current paragraph target skills
primary affordance: Start check / Verder oefenen
secondary affordance: suggest Redeneren, Rekenen, or Grafieken
hidden by default: full skill tree, dependency graph, all-skill catalog
```

Until that shared contract exists, L1.7B may define the checkpoint contract but
should not close a scalable exit-ticket implementation.

## Review Requirements

Before the exit ticket enters the scalable paragraph contract, a human review
must confirm:

- a student understands the task and next action;
- the surface feels like a checkpoint, not a test or grade;
- feedback is useful without becoming diagnostic/mastery language;
- next-practice suggestions are framed as advice, not automatic routing;
- teacher-learning quality supports retention and transfer;
- mobile/dark/keyboard behavior is acceptable;
- no blocked-use language appears.

## Acceptance Criteria For Future MVP

The future MVP may be accepted only if:

- engine/source files are source-controlled in the platform repo;
- paragraph data is generated/deployed through the platform workflow;
- the lesson output is not hand-patched;
- landing-page placement follows the route hierarchy;
- validator support checks the exit-ticket schema;
- screenshots/interaction QA pass;
- student-experience and teacher-learning-quality review return PASS or PASS
  WITH FLAGS;
- the quality-ref records the checkpoint status honestly.
