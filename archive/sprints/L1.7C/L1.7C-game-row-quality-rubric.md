# L1.7C Game-Row Quality Rubric

Date: 2026-05-23
Status: ACTIVE RUBRIC

## Verdict Values

Use one verdict per game family:

- `ready`: acceptable for controlled reuse under current gates.
- `pass_with_flags`: usable in the pilot set, with explicit non-blocking flags.
- `revise`: targeted fixes required before L1.7C can close.
- `held`: do not scale; needs a later design or platform sprint.

## Shared Criteria

| Area | Ready standard | Closure blocker |
|---|---|---|
| Skill-map route | Consumes shared skill-map contract with a scoped aspect route. | Uses an unfiltered all-skill catalog by default or invents its own route semantics. |
| Product boundaries | Uses practice-only language; no mastery, diagnostics, automatic sequencing, grading, summative, AI, PV projection, or PV machine-promotion claim. | Student-facing text claims mastery/diagnosis/grade/pass-fail routing or implies adaptive sequencing. |
| Feedback | Wrong answers receive specific next action or explanation. | Generic `wrong` feedback, silent failure, or answer reveal before a real attempt. |
| Scaffolding | Help appears before or after attempts in a way that supports learning without removing the task. | The default state reveals the answer path so the game becomes copying. |
| Success state | Student understands what was practised and what to try next. | Confusing score/perfect/pass language or unclear end state. |
| Replay value | Tasks can be repeated without becoming purely memorized after one run. | Static single answer path with no variation and no reason to replay. |
| Mobile/dark/keyboard | Controls fit and remain operable in mobile/dark mode with keyboard focus. | Clipped controls, invisible text, inaccessible form sequence, or off-screen graph/table. |
| MTU/procedure/visual alignment | Route refers to the paragraph's real skills and procedures where available. | Skill route contradicts paragraph target skills or visual/procedure evidence. |

## Redeneren

Ready standard:

- route filter: `reasoning`;
- tasks require causal/procedural reasoning construction, ordering, or matching;
- feedback explains why a relation or step order is wrong;
- no pure recognition-only path as the dominant experience.

Likely blockers:

- correct order is exposed before attempt;
- wrong answers only say incorrect without explaining relation/step mismatch;
- game labels a recognition task as reasoning.

## Rekenen

Ready standard:

- route filter: `calculation`;
- where relevant, UI separates calculation field, final answer field, and unit;
- feedback distinguishes wrong selected values, wrong calculation, and missing
  unit;
- procedure steps remain consistent with procedure-contract data.

Likely blockers:

- procedure-card selection replaces actual calculation when the paragraph needs
  arithmetic practice;
- no unit handling where the target skill requires a unit;
- unsafe auto-correct or answer-revealing defaults.

## Grafieken

Ready standard:

- route filter: `graphical`;
- visual source is present and semantically correct;
- at least one harder variant reduces direct value labels or requires axis/grid
  reading rather than copying a labelled point;
- feedback distinguishes reading the wrong axis/value from calculation errors.

Likely blockers:

- graph visual does not match task values;
- default values are so directly labelled that the game never tests graph
  reading;
- graph axis semantics conflict with economics conventions.

## L1.7C Disposition Rule

L1.7C may close only if each game family is at least `pass_with_flags` and the
flags are explicit. If any family is `revise` or `held`, L1.7C remains open or
closes only as a stop/hold decision with the next sprint named.
