## Goal

Close the follow-up issues from the second §1.1.1 web PowerPoint review without reopening the whole L1.5D sprint. ## Operationalized sprint procedure

1. Inspect current source/output state.
   - Confirm Part A still contains a 3-step B02 procedure.
   - Confirm Part B companion surfaces contain canonical 4-step B02.
   - Confirm the presentation HTML currently derives weak nav labels from prominent numeric slide text.
   - Stop if the local platform worktree has unrelated edits in target files.

2. Fix Part A content parity.
   - Replace all student-facing 3-step B02 tables and summaries with the canonical 4-step sequence:
     1. benoem alternatieven;
     2. bereken opbrengst per alternatief;
     3. rangschik; beste niet-gekozen opbrengst = alternatieve kosten;
     4. bereken nettowaarde = opbrengst gekozen alternatief - alternatieve kosten.
   - In worked examples and answer tables, include the nettowaarde row.
   - Standardize the farmer context as `winst`/`totale winst` where the source numbers are profit per hectare, while keeping generic B02 wording as `opbrengst` or `waarde`.
   - Soften absolute wording: use "Volgens deze opbrengstmaat..." instead of implying all decisions are monetary-only.

3. Fix the presentation source and web conversion.
   - Add a compact learning-goal strip to the Lisa slide.
   - Add explicit per-slide nav metadata in speaker notes and teach the converter to use it.
   - Render two-option slides as semantic option cards in HTML.
   - Add a global speaker-notes toggle; keep notes collapsed by default for student readability.
   - Shorten the dense summary slide and soften the "opbrengst > alternatieve kosten" wording.
   - Ensure the converter chooses the official `presentatie.pptx`, not a local prototype deck, when multiple presentation-like PPTX files exist in the paragraph folder.

4. Add a parity validator gate.
   - When `quality-ref.yaml` declares `procedure_b02_step_count: 4`, complete-mode validation must scan Part A markdown plus the relevant Part B web surfaces for B02 drift.
   - Fail on legacy `drie stappen` / `3-stappen` wording or absence of a visible fourth step/nettowaarde signal.

5. Regenerate through existing platform/paragraph workflows.
   - Run the presentation builder from `4veco-platform`.
   - Run `convert_presentatie.py` for the paragraph.
   - Run the paragraph `build_pdf.py` to regenerate Part A HTML/PDF.
   - Deploy if needed to sync shared CSS/landing references.

6. Verify and record.
   - Run targeted jest tests and `validate-paragraph.js --mode complete`.
   - Run the PPTX accessibility audit.
   - Render/inspect presentation HTML at desktop and 390px mobile, including slide 2, slide 5, and notes toggle.
   - Update `1.1.1-review.md` and `1.1.1-quality-ref.yaml` with the corrected B02 state and test evidence.
