# L1.5G-A Graphical Game Scope Cut And Prototype Audit

Date: 2026-05-16
Owner: Codex main agent
Status: closed - PASS

## Purpose

Decide what part of the standalone GrafiekMeester prototype should become the
first platform-owned graphical-game MVP, before any engine or generated lesson
output is changed.

The original L1.5G scope was too large for one closure gate: graphical game,
three-aspect routing, adaptive payload seam, five-game refactor, generated
lesson integration, and PV-boundary governance. L1.5G is therefore split into
five sub-sprints:

- L1.5G-A: graphical game scope cut and prototype audit
- L1.5G-B: adaptive input seam contract
- L1.5G-C: graphical game MVP engine
- L1.5G-D: three-aspect game routing
- L1.5G-E: integration, QA, and review gate

## Decision

Do not port GrafiekMeester directly. Treat it as a design reference.

The first MVP should focus on graph reading and value selection only:

- read a value from a bar chart;
- read a value from a line chart;
- select old/new values from a graph and calculate percentage change;
- give feedback in the order `bron -> waarden -> berekening`.

The first technical target should be a bounded sandbox or the already-polished
`1.1.2 Percentages en indexcijfers` route. The first production regression
target should remain L1.6, preferably `1.1.3 Grafieken en tabellen`, because
that is the natural paragraph for graph/table reading.

## Explicit Non-Goals

- no code migration in L1.5G-A;
- no new engine files;
- no generated lesson output;
- no XP economy;
- no campaign mode;
- no full skill tree;
- no badges;
- no AI coach;
- no adaptive behavior;
- no diagnostics, mastery routing, sequencing, or summative use;
- no PV machine promotion;
- no student-facing PV projection;
- no direct port of the broad producer, elasticity, market-graph, or
  cross-domain progression material.

## Required Follow-Up Sprints

L1.5G-B must define the adaptive payload seam before L1.5G-C builds the sixth
game, so the graphical game and existing games read the same empty/default
contract without changing behavior.

L1.5G-C must create platform-owned engine, UI, CSS, shell generator, data
schema, and tests for the narrow MVP.

L1.5G-D must make the student route understandable as one graphical learning
aspect, not as another unlabelled game tile.

L1.5G-E must close only after generated lesson output is reachable, visually
checked, validated, and reviewed.

- promotes PV records into `references/machine`;
