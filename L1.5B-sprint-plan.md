## Scope

In scope:

- Update platform-owned landing-page generator and CSS emitted by
  `build-landing-page.js`.
- Add `data-domain` or equivalent stable hooks to book/chapter cards so the
  generated indexes can use the same editorial accent model as companion pages.
- Replace broad/undifferentiated pitfall presentation with per-card pitfalls
  where the landing-page data model supports it.
- Improve card density, section hierarchy, light/dark behavior, and mobile
  robustness only where the fix belongs in the reusable generator.
- Regenerate the affected Book 1 landing/index pages through `deploy.js`.
- Validate both pilot paragraphs (`1.1.1`, `1.1.2`) and Book 1 health.
- Run the procedure-contract validator as a hard post-layout gate.

Out of scope:

- New PV procedure semantics.
- PV machine promotion or student-facing PV projection.
- L1.5G game work or adaptive-input refactors.
- Broad paragraph production.
- Hand-patching generated lesson HTML.
- Reopening Part A textbook content unless validation proves the generator
  accidentally damaged Part A routes.

## Work Procedure

1. Baseline current generated output:
   - inspect current Book 1 root, chapter 1.1, `1.1.1`, and `1.1.2` index
     pages;
   - note current card hooks, dark-mode behavior, and pitfall rendering.
2. Implement generator changes in platform:
   - add stable domain/accent hooks to `.chapter-card` and `.para-card`;
   - add CSS rules using existing theme variables;
   - implement per-card pitfall output only from available structured data,
     with graceful fallback when no pitfall data exists.
3. Add focused tests:
   - card markup includes the expected hook;
   - no visible `HTML` chip returns;
   - Word-download task rows remain hidden by default;
   - per-card pitfalls render only when meaningful data exists.
4. Regenerate Book 1 landing/index output:
   - `node scripts\deploy.js "..\4veco-lessen\Boek 1 - Grondslagen, vraag en aanbod"`
5. Validate hard gates:
   - `npm.cmd test -- scripts/tests/build-landing-page.test.js --runInBand`
   - `node scripts\validate-procedure-contracts.js --book-root "..\4veco-lessen\Boek 1 - Grondslagen, vraag en aanbod"`
   - `node scripts\validate-paragraph.js --mode complete --profile student-web "<1.1.1 folder>"`
   - `node scripts\validate-paragraph.js --mode complete --profile student-web "<1.1.2 folder>"`
   - `npm.cmd run check:book -- "..\4veco-lessen\Boek 1 - Grondslagen, vraag en aanbod"`
6. Visual QA:
   - desktop and narrow/mobile screenshots for Book 1 root, chapter 1.1,
     `1.1.1` index, and `1.1.2` index;
   - light and dark mode checks;
   - confirm card text does not overflow and no elements overlap.
7. Diff review:
   - no internal codes (`B02`, `A61`, `A38`, `A39`) in student-facing landing
     copy;
   - no stale `drie stappen`/`3 stappen` wording returns;
   - no generated Office-download rows return;
   - no PV projection or adaptive/diagnostic wording appears.

## Acceptance Tests

L1.5B can close only when:

- landing generator tests pass;
- procedure-contract validation passes;
- `1.1.1` and `1.1.2` complete student-web validation pass;
- Book 1 `check:book` passes;
- visual QA confirms the changed indexes work in light/dark and desktop/mobile;
- generated output was produced through platform workflow;
- roadmap and sprint plan contain closure evidence.

## Stop Conditions

Stop before implementation or commit if:

- the generator needs content that is not available in structured data and
  would require invented pitfall text;
- any landing-page fix requires hand-editing generated lesson HTML;
- procedure-contract validation fails after a layout-only change;
- internal codes become visible in student-facing output;
- Word/legacy task rows or visible `HTML` chips return;
- the implementation starts touching L1.5G game/adaptive work;
- the change would imply PV machine promotion or student-facing PV projection.
