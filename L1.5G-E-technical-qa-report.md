## Human-Review Revision Response

The human review returned `REVISE` because the first game build could reveal
answers through placeholders and did not yet make old/new value selection
explicit enough for student practice.

The closure-blocking issues were fixed in platform source and regenerated into
the lesson target:

- numeric answer placeholder is now neutral: `Typ je antwoord`;
- percentage answer placeholder is now neutral: `Typ je percentage`;
- old/new selectors start with explicit placeholders: `Kies oude waarde` and
  `Kies nieuwe waarde`;
- old/new selectors are required before checking a percentage-change answer;
- each challenge now shows a visible pre-answer checklist;
- wrong-answer feedback now includes a diagnostic line for missing selection,
  wrong old/new value, or calculation error.

## Focused Re-Review Revision Response

The focused re-review returned `REVISE` because the final challenge feedback
was skipped. After the final answer was recorded, `render()` saw
`engine.isComplete()` and jumped directly to the summary.

The closure-blocking issue was fixed in platform source and regenerated into
the lesson target:

- summary rendering now waits until the engine is complete and no `lastResult`
  feedback is pending;
- the final challenge now displays feedback first;
- `Bekijk resultaat` then opens the summary;
- the graphical UI safeguard test now checks that the old `engine.isComplete()`
  short-circuit does not return.
